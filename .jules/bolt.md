## 2025-05-21 - Unbounded Caching Risks in Knowledge Graph Architecture
**Learning:** Attempting to cache dynamic knowledge graph responses (like Zep) in long-lived, unbounded class-level dictionaries is a critical anti-pattern. While it solves the problem of per-request instantiation rendering `@lru_cache` useless, it introduces severe memory leaks (no size limits/eviction) and serves stale data (no invalidation triggers when external processes or LLMs update the graph). Using `copy.deepcopy` on large result sets also negates the performance benefit.
**Action:** When working with dynamic memory stores or knowledge graphs, avoid caching queries entirely unless using a proper caching layer (like Redis) with explicit invalidation rules tied to mutation events. For frontend list rendering, prefer Vue's `v-memo` over manual caching to prevent unnecessary virtual DOM updates without risking state desynchronization.
