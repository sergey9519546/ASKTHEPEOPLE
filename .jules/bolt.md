## 2024-05-24 - Thread-safe caching for Zep API requests
**Learning:** Adding caching to a Flask service instantiated per-request requires class-level state (e.g., static variables). However, this shared state must be protected with locks (`threading.Lock()`) in multi-threaded environments like Flask to prevent `RuntimeError: dictionary changed size during iteration` or `KeyError` during concurrent accesses or eviction. Additionally, using `copy.deepcopy` ensures returned cached objects aren't accidentally mutated by callers. Modifying dependency lockfiles like `uv.lock` automatically when not requested can introduce unintended breaking upgrades.
**Action:** Always use thread-synchronization primitives (`threading.Lock()`) when implementing class-level or global caches in a web backend. Verify the project's dependency boundaries before committing any lockfile changes.
