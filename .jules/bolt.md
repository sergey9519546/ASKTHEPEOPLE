## 2024-05-24 - Vue 3 v-memo Reactivity Trap
**Learning:** When using `v-memo` in Vue 3 to optimize large list rendering (like in HistoryDatabase.vue), passing the reactive object itself (e.g., `v-memo="[project]"`) completely breaks reactivity. Vue evaluates dependencies using strict equality (`===`), so mutating a property inside the object doesn't change the object's reference, causing `v-memo` to incorrectly skip the re-render. Additionally, including list-wide properties like `projects.length` inside individual item dependency arrays defeats the purpose of memoization by forcing O(N) re-renders when items are added/removed.
**Action:** When implementing `v-memo` optimizations, always explicitly track the specific primitive properties that drive the component's state (e.g., `v-memo="[project.id, project.status]"`). Never include the whole reactive object or properties that change for the entire list (unless updating all items is intended).
